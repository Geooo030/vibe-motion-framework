# 热点君：三期制作与 Git 管理

## 本次需求

以当前 Blender + Remotion 热点君框架制作三期原创科技/科普/热点评论视频，适合 Bilibili 和抖音。这里把「bilibili 和抖音相关」暂按发布平台理解；若用户指定讨论这两个平台本身，再调整选题。爆款是创作目标，不是流量保证。

参考账号：https://space.bilibili.com/1752456213
既有参考：https://www.bilibili.com/video/BV1abuA6pES2/

实际观看多条可访问的视频，记录可核验的布局、字体层级、镜头节奏、信息高亮与声画关系。参考叙事方法，不搬运文案、画面、品牌或音乐；无法播放时明确观察限制。

## 分支与交付

- `main`：可复用框架和公共制作工具，不混入某期的素材依赖。
- 每期一个 `episode/<编号>-<主题>` 分支；框架改动与单期内容分别提交。
- 每期目录 `episodes/<编号>/`：`brief.md`、`script.md`、`sources.json`、`shots.json`、`assets.json`、`audio/`、`qc.md`。
- 每个镜头有稳定 ID，例如 `s010`。shots 清单记录旁白、整数帧起止、场景入口、素材 ID、渲染参数及校验值；明确 fps 与端点是否包含。
- 先得到实际 TTS 音频及时间戳，再定镜头长度；不能把长旁白硬塞进旧的七秒样片。字幕重叠、尾句被截断、空白镜头必须检查。
- 按脚本、镜头、配音对齐、混音、验收分别提交，提交消息附期数和镜头 ID。不要为每帧生成 Git commit。
- 小型原创素材可入 Git。模型权重、缓存、PNG 序列和大成片留在忽略目录；用清单保存来源、版本、SHA-256、重建命令和本地输出路径。确需大文件托管时先确认 Git LFS 可用及配额，不静默开启收费存储。
- 三个分支都推送到指定仓库，不强推、不覆盖远端历史。交付本地可播放成片、字幕、封面、来源及每期分支链接；不自动发布到视频平台。

## 声音与音乐

在 GitHub 调研可用的中文 TTS/声音克隆模型，对比许可证、模型权重许可、商用限制、中文韵律、硬件占用、部署难度和时间戳能力。实际测试至少一个适合本机的方案；没有授权的真人样本时先用原创/标准音色，不抓取参考 UP 主音频做克隆。不要把虚拟环境中的凭据、Cookie 或参考人物声音样本推送到仓库。

本机已有云希和晓晓试听（edge-tts 7.2.8），文件在 `public/blender/narration/`。它们不是开源模型部署成果，也不是差评君的声音。豆包 Skill 的 `MODEL_SPEECH_API_KEY` 当前未配置。既有试听文案为：「同一个基准，两个版本。从六十一点八，提升到八十二点七。镜头靠近，重点就清楚了。」云希音频约 8.52 秒，现有画面仅 7 秒，尚未混合；SRT 前两句有约 50 ms 的重叠，正式使用前需修正。

BGM 使用原创合成音乐或可验证授权的曲目，登记许可证/作者/来源/署名要求；不提取参考视频背景音乐。旁白优先，做 BGM ducking、淡入淡出和响度检查，确认最终 MP4 有可听的人声且无削波。

## 验收

每期核查事实来源与时间，区别厂商数据与独立测试，示意数据明确标注。运行 lint/类型检查，检查每个镜头的关键帧、竖屏安全区、字幕对齐、音轨时长、片尾保持和最终编码。只有实际导出并验证的文件才标记为已完成。模型或音色选型受限时报告实测结果并提供已可用的配音版本，不把研究报告冒充三期成片。
